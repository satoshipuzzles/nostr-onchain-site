# Nostr Onchain — site

Landing page and product pages for the Nostr Onchain suite. Static HTML/CSS with a few Vercel serverless functions under `api/`. Hosted on Vercel; deploys automatically from `main`.

## Domains

- `nostronchain.com` (canonical, catalog + product pages + `/store` preorder + `/nip05` paid identifier service)
- `pocketsigner.com` (aliased, `/` redirects to `/pocket-signer`)

## Environment variables

Set these in the Vercel project dashboard (Settings → Environment Variables) for the `Production` and `Preview` environments.

| Name | Purpose | Where used |
|---|---|---|
| `STORE_NPUB` | Store's Nostr pubkey (bech32 `npub1...`). Its BIP-86 taproot address receives the 21k-sat NIP-05 registration payment. Same key already used by `/store`. | `api/nip05/_lib.js`, `nip05.html` (hardcoded fallback) |
| `UPSTASH_REDIS_REST_URL` | Auto-populated by the Vercel Marketplace Upstash Redis integration. Legacy `KV_REST_API_URL` also honored. | `@upstash/redis` |
| `UPSTASH_REDIS_REST_TOKEN` | Auto-populated. Legacy `KV_REST_API_TOKEN` also honored. | `@upstash/redis` |
| `CRON_SECRET` | Auto-generated by Vercel Cron. Guards the snapshot endpoint. | `api/cron/nip05-snapshot.js` |
| `SNAPSHOT_PUSH_TOKEN` | (Optional) A GitHub PAT with `repo` scope on this repo, used by the nightly snapshot to commit `data/nip05-snapshot.json`. If unset, the snapshot is only logged. | `api/cron/nip05-snapshot.js` |

## Redis (KV) setup

The NIP-05 flow requires an Upstash Redis database attached via Vercel Marketplace:

1. Vercel dashboard → Storage → Marketplace → **Upstash → Redis**.
2. Attach to the `nostr-onchain` project (Production + Preview).
3. The `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN` env vars appear automatically.

If you're on the legacy Vercel KV product, `KV_REST_API_URL` / `KV_REST_API_TOKEN` are honored as fallbacks — no code change needed.

## Local dev

```bash
cd site
npm install
vercel dev
```

Vercel Dev serves the static files + runs the `api/*` functions locally. You'll need a `.env.local` with `STORE_NPUB` and mock KV credentials (or point at the real KV) for the NIP-05 endpoints to work.

## Deploy

Push to `main` and Vercel auto-deploys within ~1 minute. To force a deploy without a commit: `vercel --prod` from this directory.

## What lives where

| Path | Purpose |
|---|---|
| `index.html` | Product catalog (canonical only on nostronchain.com) |
| `store.html` | `/store` — Pocket Signer preorder |
| `pocket-signer.html` | `/pocket-signer` — Pocket Signer marketing |
| `nip05.html` | `/nip05` — paid NIP-05 identifier service |
| `client.html`, `nostrtx.html`, `signer-link.html`, `bridge.html` | Marketing pages for the other products |
| `api/nip05/check.js` | Name availability lookup |
| `api/nip05/claim.js` | Submit a paid claim (verifies payment + provisions) |
| `api/nip05/well-known.js` | Serves `/.well-known/nostr.json` |
| `api/cron/nip05-snapshot.js` | Nightly public snapshot of the registry to `data/nip05-snapshot.json` |
| `data/nip05-reserved.txt` | Names the operator holds |
| `data/nip05-snapshot.json` | Nightly generated public snapshot of the registry (for transparency + audit) |
